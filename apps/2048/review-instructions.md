# 지침: 2048 게임 웹앱 — Review 단계

## 배경
이 저장소는 마크다운 기반 블로그 + 미니 웹앱 포트폴리오다. 프로젝트 루트의 CLAUDE.md에 정의된 작업 사이클(Plan → Build → Review → Embed)을 따른다. Plan(spec.md)과 Build(index.html/style.css/script.js) 단계가 끝났다. 지금은 Review 단계만 수행한다. 너는 Build를 진행한 서브에이전트와 별개의 독립적인 검증자다.

## 목표
`D:\Claude_code\Harness\apps\2048\` 에 구현된 2048 게임이 `spec.md` 설계와 요구사항대로 제대로 동작하는지 검증한다.

## 검증 범위
1. `D:\Claude_code\Harness\apps\2048\spec.md`를 읽고 요구사항을 파악한다.
2. `index.html`, `style.css`, `script.js` 코드를 리뷰해서 버그, 오타, 잘못된 로직이 없는지 확인한다.
3. 정적 서버(예: `npx live-server` 또는 임시 http 서버)를 이 폴더에서 띄워 실제 브라우저에서 열어본다.
4. 다음을 직접 테스트한다:
   - 초기 로드 시 타일 2개 생성, 콘솔 에러 없음.
   - 방향키(상하좌우)로 타일이 정상적으로 밀리고 병합되는지.
   - 같은 숫자 타일이 합쳐질 때 점수가 정확히 오르는지.
   - 이동해도 보드에 변화가 없는 방향키 입력 시 새 타일이 생기지 않는지 (스팸 방지 로직).
   - "New Game" 버튼 클릭 시 점수 초기화, 최고 점수(localStorage)는 유지되는지.
   - 모바일 뷰(좁은 화면)에서 레이아웃이 깨지지 않는지 (반응형 확인).
   - 게임 오버 / 승리(2048 타일) 조건이 맞게 동작하는지 (코드 리뷰로 로직 검증, 실제로 2048까지 플레이할 필요는 없으나 로직이 맞는지는 꼼꼼히 확인).
5. 문제를 발견하면 **직접 수정**한다 (CLAUDE.md 규칙: "문제가 있으면 수정한다").
6. 검증 결과를 `D:\Claude_code\Harness\apps\2048\review.md`로 저장한다. 발견한 문제, 수정 내역, 최종 결론(정상 동작 여부)을 포함한다.

## 범위 제한 (반드시 지킬 것)
- `/apps/2048/` 폴더 안의 파일만 읽고 수정한다 (`index.html`, `style.css`, `script.js`, 필요시 `review.md` 작성).
- `/apps/2048/` 폴더 밖의 파일(블로그 메인 페이지, CLAUDE.md 등)은 절대 건드리지 않는다.
- `spec.md`, `plan-instructions.md`, `build-instructions.md`는 수정하지 않는다.
- 정적 서버를 띄웠다면 검증 후 반드시 종료한다.
