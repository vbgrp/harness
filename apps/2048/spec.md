# 2048 게임 웹앱 — 구현 계획 (spec.md)

## 개요
순수 HTML/CSS/JavaScript로 만드는 2048 퍼즐 게임. `/apps/2048/` 폴더 안에서 완전히 자체 완결되며, 외부 라이브러리 없이 동작한다. 방향키와 터치 스와이프 양쪽 조작을 지원하고 점수판(현재 점수 + localStorage 기반 최고 점수)을 포함한다.

## 1. 파일 구조
```
apps/2048/
├── index.html   # 마크업: 헤더, 점수판, 게임 보드, 오버레이 메시지
├── style.css    # 레이아웃, 타일 색상, 반응형, 애니메이션
└── script.js    # 게임 상태, 입력 처리, 렌더링, localStorage
```
- 세 파일만 사용. 이미지/폰트는 CSS(box-shadow, border-radius, system font)로 대체하여 외부 리소스 의존을 없앤다.

## 2. 화면 레이아웃 (index.html 구성)
1. **헤더 영역**
   - 타이틀 "2048" (h1)
   - 짧은 설명 텍스트: "타일을 합쳐 2048을 만들어보세요!"
2. **점수판 영역** (헤더 우측 또는 하단, flex 배치)
   - `SCORE` 박스: 현재 점수 (`#score`)
   - `BEST` 박스: 최고 점수 (`#best-score`, localStorage 연동)
3. **컨트롤 영역**
   - "New Game" / "다시 시작" 버튼 (`#restart-btn`) — 언제든 클릭 시 즉시 재시작
4. **게임 보드**
   - `#game-board`: 4x4 CSS Grid 배경 셀(16개, 빈 칸 표시용) + 타일 레이어(`#tile-container`, 절대 위치로 타일 렌더링)
5. **오버레이 메시지** (`#game-message`, 기본 숨김)
   - 승리 시: "You Win!" + "계속하기" / "새 게임" 버튼
   - 게임 오버 시: "Game Over!" + "다시 시작" 버튼
6. **하단 안내**
   - "방향키로 이동하세요. 모바일에서는 스와이프하세요." 문구

## 3. 핵심 로직 설계 (script.js)

### 3.1 상태 관리
- 보드는 4x4 2차원 배열(`board[row][col]`)로 표현, 값은 0(빈 칸) 또는 2의 거듭제곱.
- 전역 상태 객체 예: `{ board, score, best, isGameOver, hasWon }`.

### 3.2 초기화
- `initGame()`: board를 0으로 채우고, 랜덤 위치 2곳에 타일 생성(각각 90% 확률로 2, 10% 확률로 4) 후 렌더링.
- localStorage에서 `best-score` 값을 읽어와 표시.

### 3.3 이동/병합 알고리즘
- 네 방향(상하좌우)을 각각 별도로 구현하지 않고, **왼쪽 이동 기준의 공통 함수**(`slideAndMergeRow(row)`)를 만들고, 다른 방향은 배열을 회전(rotate)/뒤집기(reverse) 시킨 뒤 왼쪽 이동을 적용하고 다시 원상 복구하는 방식으로 구현하여 중복을 줄인다.
  - `slideAndMergeRow`: 0이 아닌 값만 추출 → 왼쪽부터 순회하며 인접한 동일 값을 한 번만 병합(병합된 타일은 그 턴에 재병합되지 않도록 플래그 처리) → 병합 시 점수 누적 → 나머지를 0으로 패딩.
  - 이동 전/후 보드를 비교하여 실제로 변화가 있었는지(`moved` 플래그) 판정 — 변화가 없으면 새 타일을 생성하지 않는다(빈 방향키 입력 방지).
- 병합될 때마다 `score += mergedValue` 로 누적하고, `mergedValue === 2048`이고 아직 승리 처리 전이면 승리 플래그 설정.

### 3.4 랜덤 타일 생성
- `spawnRandomTile()`: 빈 칸 좌표 목록을 구해 그중 하나를 무작위 선택, 90%/10% 확률로 2 또는 4 배치.
- 이동이 실제로 발생한 경우에만 이동 후 호출.

### 3.5 승리/패배 판정
- **승리**: 보드에 2048 타일이 처음 등장하면 오버레이로 "You Win!" 표시하되, "계속하기" 선택 시 게임을 이어갈 수 있도록 한다(승리 후에도 게임 오버 조건까지는 계속 플레이 가능).
- **게임 오버**: 보드가 가득 찼고(빈 칸 없음), 상하좌우 어느 방향으로도 인접한 동일 값이 없어 더 이상 병합 불가능할 때 판정. 매 이동 후 이 조건을 체크.

### 3.6 점수 계산 및 localStorage
- 현재 점수는 매 병합마다 누적, 화면에 즉시 반영.
- 최고 점수는 `localStorage.getItem('game-2048-best-score')`로 로드, 현재 점수가 이를 초과할 때마다 `localStorage.setItem(...)`으로 갱신.
- 재시작 시 현재 점수는 0으로 초기화되지만 최고 점수는 유지.

### 3.7 입력 처리
- **키보드**: `keydown` 이벤트에서 `ArrowUp/Down/Left/Right` 감지, `event.preventDefault()`로 페이지 스크롤 방지 후 해당 방향 이동 함수 호출.
- **터치(모바일 스와이프)**: `touchstart`에서 시작 좌표 기록, `touchend`에서 종료 좌표와의 차이(Δx, Δy) 계산. 최소 스와이프 거리(예: 30px) 이상이고, |Δx| vs |Δy| 중 더 큰 쪽을 기준으로 방향 결정. `touchmove`에서 `preventDefault()`로 화면 스크롤/바운스 방지.

## 4. UI/UX 요소

### 4.1 타일 색상 (값별 매핑)
- 2: `#eee4da`, 4: `#ede0c8`, 8: `#f2b179`, 16: `#f59563`, 32: `#f67c5f`, 64: `#f65e3b`, 128: `#edcf72`, 256: `#edcc61`, 512: `#edc850`, 1024: `#edc53f`, 2048: `#edc22e`(골드, 강조 box-shadow).
- 128 이상은 흰색 텍스트, 그 이하는 진한 갈색(`#776e65`) 텍스트로 대비 확보.
- 값이 커질수록(4자리 이상) `font-size`를 자동으로 줄여 타일 안에 들어가도록 처리.

### 4.2 애니메이션
- 새로 생성된 타일: `scale(0) → scale(1)` 트랜지션으로 팝인 효과 (`tile-new` 클래스, CSS `@keyframes`).
- 병합된 타일: 잠깐 확대 후 축소되는 펄스 효과 (`tile-merge` 클래스).
- 이동 애니메이션은 1차 구현에서는 생략하고 즉시 재배치(단순화) — 필요 시 추후 `transform: translate` 기반 슬라이드 애니메이션을 Build 단계에서 스트레치 목표로 추가 가능하다고 명시.
- 오버레이(승리/게임오버) 등장 시 `opacity` 페이드인.

### 4.3 반응형 레이아웃
- 게임 보드 크기: `min(90vw, 90vh, 500px)` 형태로 CSS에서 정의하여 데스크톱/모바일 모두 화면을 벗어나지 않게 함.
- `aspect-ratio: 1 / 1`로 보드를 항상 정사각형 유지.
- 타일 간격(gap)과 폰트 크기는 보드 크기에 비례한 상대 단위(`%`, `vmin`, 또는 CSS 변수 계산)로 지정.
- 뷰포트 메타 태그(`<meta name="viewport" content="width=device-width, initial-scale=1">`)로 모바일 배율 고정.
- 터치 영역 확대를 위해 버튼과 오버레이 버튼은 최소 44px 터치 타겟 확보.

### 4.4 재시작 버튼 및 기타 컨트롤
- 상단 "New Game" 버튼: 언제든 클릭 가능, 클릭 시 확인 없이 즉시 새 게임 시작(캐주얼 게임 특성상 확인 다이얼로그 불필요).
- 오버레이 내부에도 "다시 시작" 버튼 배치(게임 오버/승리 시 접근성 향상).
- 키보드 포커스가 버튼에 있어도 방향키 입력이 게임에 반영되도록 이벤트는 `window` 레벨에 바인딩.

## 5. 접근성 및 예외 처리
- 모든 버튼에 적절한 `aria-label` 부여.
- 점수판 값 변경 시 `aria-live="polite"` 속성으로 스크린리더 알림(선택 사항).
- 빠른 연속 키 입력 시 이전 이동 애니메이션이 끝나기 전 다음 입력을 막기 위한 간단한 `isAnimating` 락(선택 사항, 필요 시 Build 단계에서 결정).

## 6. Build 단계에 남기는 참고사항
- 위 설계는 구현 세부사항(변수명, 함수 분리 방식)까지 강제하지 않으며, Build 서브에이전트가 동일한 파일 구조(`index.html`/`style.css`/`script.js`)와 핵심 로직(공통 슬라이드-병합 함수, localStorage 최고점수, 방향키+스와이프 입력, 승리/게임오버 판정)을 지키는 선에서 자유롭게 구현한다.
- 이동 애니메이션(슬라이드)은 스트레치 목표이며, 시간이 부족하면 생략 가능(팝인 애니메이션만으로도 요구사항 충족).
